测试源码：[依赖实验](../../tests/p0/dependencies_test.go)、[Linux 进程实验](../../tests/p0/process_linux_test.go)。本次命令实际输出含 `SQLite 3.53.4; journal_mode=wal`；Windows 三组测试、Linux 依赖测试及 `TestLinuxProcessGroup/term`、`/kill` 全部 PASS。MCP 两平台均返回 `PASS protocol=2026-07-28`。

进程实验在测试进程启用 Linux subreaper，使 KILL 后的孤儿后代可由测试进程 wait4 回收，避免依赖 WSL PID 1。这是测试夹具机制，不是已经决定的 Node 进程监管实现。正常退出由 helper 父进程 Wait，强杀由测试进程 Wait/Wait4，最后确认子 PID/进程组不存在、输出管道 EOF；没有只检查父进程退出。

## 复现步骤

PowerShell，工作目录仓库根目录，需要 Go 1.27.0、可用 Ubuntu WSL。下载依赖需要网络；WebSocket 仅监听临时 loopback 端口，数据库用测试临时目录自动清理，构建产物写入被忽略的 `bin/`。race 需要可用 C 编译器。

```powershell
$env:GOPATH = "$PWD/.cache/gopath"
$env:GOMODCACHE = "$PWD/.cache/gomod"
$env:GOCACHE = "$PWD/.cache/gobuild"
go test ./... -count=1 -v
go test -race ./... -count=1
go vet ./...
go build -o bin/mcp-probe.exe ./cmd/mcp-probe
./bin/mcp-probe.exe check
go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 -test ./...
```

在**另一个 PowerShell 会话**设置相同缓存变量，然后执行 Linux 交叉验证，避免 GOOS 污染本机构建：

```powershell
$env:GOOS = 'linux'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go test -c -o bin/p0-linux-amd64.test ./tests/p0
go build -o bin/mcp-probe-linux-amd64 ./cmd/mcp-probe
wsl -d Ubuntu --exec /mnt/d/RunWeave/bin/p0-linux-amd64.test '-test.v' '-test.timeout=45s'
wsl -d Ubuntu --exec /mnt/d/RunWeave/bin/mcp-probe-linux-amd64 check
```

本次最初 WSL 因沙箱访问限制失败，使用获准的系统权限后运行成功。PowerShell 的带点测试参数需用引号；首次未加引号导致 `flag provided but not defined: -test`，修正后重新运行全部 Linux 测试通过。逐条检查退出码，不以后续命令成功掩盖前一条失败。

## 证据边界与下一步

Codex CLI 0.153.4 的真实外部调用仍引用[历史记录](2026-09-10-P0-MCP探针验证.md)，本次仅复验 SDK 子进程链路，没有重新调用模型，也没有推断 Codex 的实际协商版本。nanobot/loopx、完整 A02、两个真实 Node 不在本次通过范围。

本次尚未证明生产迁移器、并发写入竞争、磁盘故障、运行 deadline 的业务状态、取消竞争、超量日志、崩溃恢复、setsid 逃逸或生产单写循环。SQLite 的 busy_timeout 是读取配置确认，未作争锁耗时实验。1 MiB 验证的是库的消息读取限制，完整业务 envelope 的编码限额需在契约/接入实现中另测。
