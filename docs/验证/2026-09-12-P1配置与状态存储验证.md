## 命令与故障记录

PowerShell，仓库根目录，使用仓库忽略的 Go 缓存目录：

```powershell
$env:GOPATH = "$PWD/.cache/gopath"
$env:GOMODCACHE = "$PWD/.cache/gomod"
$env:GOCACHE = "$PWD/.cache/gobuild"
go test ./... -count=1
go vet ./...
go build -o bin/runweave.exe ./cmd/runweave
$env:CGO_ENABLED = '1'
go test -race ./... -count=1
```

WSL 构建、执行及 CLI/备份步骤见[指南](../指南/P1启动前检查与状态目录.md)。测试使用临时状态目录，不访问业务资源或调用模型。

另按指南在 Windows 实际运行构建后的 CLI：三角色 `config check` 均成功；Server 两次初始化的 ID 相同；Node 使用独立实例；完整复制 `state/p1-server` 到新备份、再复制到新恢复目录并使用新的配置打开，核对源/恢复 ID 相同且 schema 为 1。示例产物保留在 Git 忽略的 `state/`，没有纳入版本库。Linux 产品二进制实际返回 `version: 0.0.1-dev`、`stage: p1-foundation`。

WSL 首次在沙箱内返回 `Wsl/Service/E_ACCESSDENIED`；使用获准的系统权限后实际测试通过。Windows race 在沙箱及获准系统权限下均以 `ThreadSanitizer failed to allocate ... (error code: 87)` 失败，包括未修改的 P0 包，失败发生于检测器初始化。没有修改系统安全设置或降低测试断言来获得通过。下一步在可用的 race 运行环境中补测；本次结果不能标记 race 通过，也不能判断为发现了 Go 数据竞争。
