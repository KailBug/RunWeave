# P1 单节点实现

状态：现行，阶段进行中。更新日期：2026-09-14。适用范围：v0.0.1-dev / P1。维护责任：当前工作项开发者。

## 目标与边界

沿用[三个月规划 P1-01～08](../../RunWeave3个月开发规划书.md)，目标为真实客户端经 MCP → Server → 单个 Node 完成授权的非递归 `fs.list`，持久查询同一 execution，并具备基础幂等、取消、UNKNOWN 占槽、对账和结果确认。P0 契约是输入，P1 不改写其状态/摘要规则。

第一批入口/存储基础之后，第二批已实现 Server HTTP daemon、两类身份管理、在线撤销、凭据限权读写和 TLS 认证检查。执行服务、Node 注册/对账、业务 execution 表和 MCP bridge 尚未实现，`/readyz` 固定 503，不把认证成功当作服务可接单。阶段仍进行中；证据分别见[首批验证](../验证/2026-09-12-P1配置与状态存储验证.md)和[第二批验证](../验证/2026-09-14-P1身份与Server验证.md)，取舍见 [ADR 0005](../决策/0005-P1配置与状态存储基础.md)、[ADR 0006](../决策/0006-P1身份与Server生命周期.md)。

## 首批流程与失败行为

`config check` 有界读取文件 → 严格解析 → 语义校验 → 以配置目录解析路径 → 返回脱敏摘要。它不创建目录、不读 token、不检查远端服务，也不检查证书/资源文件是否存在。

`state init` 先完成相同配置检查；仅 Server/Node 可用。建立状态目录 → 非阻塞 OS 独占锁 → 检查状态文件类型 → 打开 SQLite → 配置 WAL/连接 PRAGMA → 验证历史并事务迁移 → 提交写入检查 → 关闭数据库 → 释放锁 → 输出角色、实例 ID 和 schema 版本。任一步失败不返回成功 JSON；已取得的锁会释放。初始化成功只证明当次存储检查，不预先保证未来磁盘可写。

锁的所有权在 Store 生命周期内；CLI 是短期所有者，未来 daemon 是长期所有者。实际测试用真实子进程持有 Store，覆盖第二进程拒绝、正常退出和强制退出后恢复；不是生产 daemon 或故障执行对账验收。锁文件可残留且必须保留，不能通过删锁文件绕过活跃所有者。

配置字段与目录/schema 在[参考](../参考/配置与状态存储.md)集中维护，命令与停机恢复在[指南](../指南/P1启动前检查与状态目录.md)维护。

## 第二批生命周期与身份

Server 先验证 TLS 文件，再持锁打开最新状态库、绑定监听；HTTP 停止后才关闭 Store。启动失败清理已取得的锁/连接；context 取消触发最长 5 秒 Shutdown，超时则强制关闭连接。daemon 日志只到 stderr。

身份管理 CLI 不创建第二 daemon；独立连接验证完整 Server 迁移历史，只进行身份创建/撤销短事务。每个 HTTP 请求重新查摘要和撤销状态，Node 路径 ID 必须匹配。角色混用/未知/撤销统一拒绝，认证存储故障返回不可用；已认证在途请求和后续 WebSocket 的撤销隔离不能由本批结论代替。

接口、凭据安全与本地管理权限统一见[身份与 HTTP 接入](../参考/身份与HTTP接入.md)，产品运行命令见[指南](../指南/P1身份接入与Server运行.md)。

1. P1-01/03 的 Server、凭据读写与 HTTP 身份范围已验证；待 Node daemon、MCP bridge 以及真实 Node 会话认证/撤销集成。
2. 下一工作项 P1-04：完整资源快照、配置版本、epoch、心跳与单写循环；未认证、未对账、离线节点不得调度，复用本批身份事实并实现长连接撤销。
3. P1-05：统一 Submit/Get/Cancel，事务内幂等/占槽/派发意图与持久取消；UNKNOWN 隔离保持槽位。
4. P1-06/07：Node 防重、策略复核、目录句柄边界、有界 `fs.list`、结果持久补报、状态/事件同事务及 receipt。
5. P1-08：HTTP、CLI、MCP 发现/提交/查询/取消，以及真实客户端目录调用、CLI 同 ID 与会话关闭后重开查询证据。

范围外能力仍按阶段推进：受控进程与审批 P2、双 Node P3、扩大故障矩阵 P4、文件读取/产物与发布 P5。首批不声称完成 A02/A05/A06/A10/A12/A15/A16；特别是已有实例身份持久化不能代替 execution 幂等与业务数据恢复。
