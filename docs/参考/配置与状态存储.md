# 配置与状态存储

状态：现行。更新日期：2026-09-12。适用范围：v0.0.1-dev / YAML v1 / Server schema v1 / Node schema v1。维护责任：当前工作项开发者。

## 配置格式

实现：[config.go](../../internal/config/config.go)。配置最大 64 KiB，只接受一个 YAML 文档；拒绝未知字段、重复键、锚点、别名、合并键、自定义标签、null 和错误标量类型。`version` 必须是整数 `1`，其余叶字段为字符串。可选字段省略或使用文档允许的空字符串，不能写 null。根节点及角色块必须是映射。

| 字段 | 必填/默认 | 约束 |
| --- | --- | --- |
| `version` | 必填 | `1`；与软件/MCP/Node/schema 版本分开 |
| `role` | 必填 | `server`、`node`、`mcp` 之一 |
| `state_dir` | Server/Node 必填；MCP 禁止非空 | 无首尾空白，必须指向受保护的本机磁盘目录；检查命令不创建 |
| `log_level` | 默认 `info` | `debug`、`info`、`warn`、`error` |
| `server` / `node` / `mcp` | 对应角色块必填 | 只允许本角色块，不能同时提供其他角色块 |
| `server.listen` | 默认 `127.0.0.1:7788` | IP 字面量与端口 1–65535；IPv6 用方括号；不接受 hostname 或空 host |
| `server.tls_cert_file`、`server.tls_key_file` | 默认无 | 必须成对；非 loopback 监听必填 |
| `node.node_id` | Node 必填 | 复用 P0 的 `ValidIdentifier`；本字段尚未绑定认证身份 |
| `node.server_url`、`mcp.server_url` | 对应角色必填 | 仅 HTTP/HTTPS origin；HTTP 只接受 loopback IP 字面量；无 userinfo、query、fragment 或业务路径；HTTPS 支持域名；显式端口 1–65535 |
| `node.token_file`、`mcp.token_file` | 对应角色必填 | 非空文件路径；没有内联 token 字段 |

相对路径以配置文件所在目录为基准，与执行命令的工作目录无关；不替换 `$VAR`、`${VAR}` 或 `~`。证书、token 文件只解析路径，当前不打开、不验证内容/权限；TLS 服务及身份认证尚未实现，当前没有跳过证书校验选项。IP 的 loopback 判断由 `net.IP.IsLoopback` 完成；HTTP 的 `localhost` 域名不接受，以免把名称解析当成已验证的 loopback 地址。

配置文件必须是普通文件。解析错误只返回固定诊断，不复制原始 YAML、URL 或解析器中的值；成功输出不含路径、token 或完整配置。三份合法样例：[Server](../资源/P1配置/server.yaml)、[Node](../资源/P1配置/node.yaml)、[MCP](../资源/P1配置/mcp.yaml)，由 `TestDocumentedExamples` 自动加载。合法/非法场景见 [config_test.go](../../internal/config/config_test.go)。

Node 资源、program、策略、心跳、留存等字段本批尚未开放，提供这些未知字段会报错，不表示可以不经授权使用资源。Node 完整快照与 token 身份的绑定在 P1 后续定义。

## 命令输出与错误

实现：[main.go](../../cmd/runweave/main.go)。当前命令精确为 `version`、`config check --config FILE`、`state init --config FILE`。额外参数、未知命令、缺少配置均失败；尚无 `server`、`node` 或 `mcp` 服务子命令。

- 成功：退出码 `0`，stdout 一个 JSON 对象。版本输出 `version/stage`；配置输出 `valid/config_version/role`；初始化输出 `role/instance_id/schema_version`。
- 失败：退出码 `1`，stdout 不写成功对象，stderr 记录 JSON `ERROR` 日志。固定用法错误不回显未知参数；存储错误可包含状态文件路径及系统原因，不记录凭据。
- `log_level` 控制成功诊断的最低级别，默认 `INFO`；错误保持可见。MCP stdout 隔离只完成公共入口约束，正式 stdio bridge 仍待 P1-08 验证。
- 状态初始化上下文上限 10 秒；锁是立即尝试、不排队等待。数据库 busy timeout 为 1000 ms；实际磁盘/驱动调用不构成硬实时保证。

## 目录与独占锁

每个 Server/Node 使用独立状态目录，布局如下；本批不生成其他业务状态文件。

| 文件 | 用途与保留 |
| --- | --- |
| `daemon.lock` | OS 独占锁载体；生命周期与 Store 一致，关闭后保留文件；不能删除或替换以解锁 |
| `state.db` | SQLite 主库；两种角色各自迁移，禁止跨角色复用 |
| `state.db-wal`、`state.db-shm` | SQLite 可能生成的 WAL 与共享内存配套文件；不能在运行中手工删除 |

`store.Open` 在所有数据库访问之前持锁；Windows 使用 `LockFileEx`，Linux 使用 `flock`。第二个遵守该协议的进程收到 `ErrLocked`，不会触发迁移；正常关闭或强制终止后 OS 释放所有权。其他平台明确失败。目录应由专用 OS 账号独占管理；网络盘和同账号恶意替换文件不在保证范围内。初始 lock/db/sidecar 是符号链接或目录时拒绝，但这不是抵御同账号替换竞态的安全沙箱。

新 Linux 目录模式 `0700`、新 lock/db `0600`（受 umask 进一步收紧），不自动修改已有目录权限。Windows 依赖父目录 ACL，`0600` 不能替代 Windows 权限设置。后续原始 token 的限权保存/读取属于 P1-01/03 未完成项。

## 数据与迁移

代码：[store.go](../../internal/store/store.go)、[migrate.go](../../internal/store/migrate.go)、[Server 001](../../internal/store/migrations/server/001_identity.sql)、[Node 001](../../internal/store/migrations/node/001_identity.sql)。两个角色各自 schema v1，名称版本相同不表示数据库可互换。

| 表/字段 | 含义 |
| --- | --- |
| `schema_migrations.version` | 连续正整数主键，从 1 开始 |
| `schema_migrations.name` | 内嵌 SQL 文件名 |
| `schema_migrations.checksum` | SQL 统一 CRLF→LF 后的 SHA-256 十六进制摘要；用于比对迁移历史，不是整库篡改检测 |
| `schema_migrations.applied_at` | 迁移写入的 UTC RFC3339Nano 时间 |
| `store_identity.singleton` | 唯一允许的主键值 `1` |
| `store_identity.role` | SQL CHECK 限制为该迁移所属角色 |
| `store_identity.instance_id` | `crypto/rand` 生成的 16 字节随机值，编码为 32 位十六进制；重开/恢复保持，未来 Node journal 将引用 |
| `store_identity.created_at` | 初次迁移时的 UTC RFC3339Nano 时间 |
| `store_identity.last_checked_at` | 最近一次启动写入检查的 UTC RFC3339Nano 时间，不代表服务 ready 或业务完成 |

连接数上限 1；WAL、外键、`busy_timeout=1000`、`synchronous=FULL`。后三项通过驱动 URI 参数在每次建立连接时执行，避免重连丢设置。文件路径先按 URI 编码，防止 `#`、`%`、Linux 的 `?` 被解释为数据库参数。已测试实际外键拒绝与替换连接后的设置，不宣称完成多写入者争锁耗时测试。

打开时拒绝缺失/空历史的已有库、历史缺口、未知新版本、名称/校验和改变及不合法实例身份。不做降级、不清空库。全部待执行迁移和对应历史在同一个短事务内提交，失败回滚 DDL 和历史；成功后单独提交写入检查。现有 P0 临时实验库不属于可升级产品库，不原地导入。

本批只有持久实例身份；无 executions、events、token_records、received_executions 或业务防重表。其 schema 与事务原子性随后续工作项追加；P0 的幂等契约未因此自动实现。

## 备份、恢复与兼容边界

仅支持停机完整目录复制到受保护位置。保留数据库配套文件及实例 ID；不要在线只复制 `state.db`，不要编辑迁移记录。停机复制恢复已在 Windows/WSL 测试，范围仅首批 schema/身份；不能外推 execution、产物或运行中故障恢复。操作步骤见[指南](../指南/P1启动前检查与状态目录.md)。

恢复副本检查前应确保原实例停止；未来不得把相同 Node 身份的源与副本同时上线。使用比库更旧的软件会明确失败，应恢复与旧软件匹配的停机备份，而非删版本行。丢失 Node 状态后，后续接入必须撤销旧身份并重新创建，不能把新实例当成保留了旧 journal。
