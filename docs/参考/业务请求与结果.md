# 业务请求与结果

状态：现行，纯契约实现与验证已完成。更新日期：2026-09-11。适用范围：P0-02 / 业务契约 v1；不是已可调用的 HTTP/MCP 接口。维护责任：当前工作项开发者。

设计依据：[ADR 0002](../决策/0002-业务契约与请求摘要.md)。本页定义业务字段；Node envelope、ExecutionView 状态和消息由 P0-03 单独定义。

## 请求与边界

JSON 根必须是单个对象。所有层级字段名精确区分大小写，未知字段、重复键、null、无效 Unicode、深度超过 32 和多个根值均拒绝；整数仅十进制整数字面量。请求原始 UTF-8 JSON（含空白）与规范化后完整请求的 JSON 编码均最多 65,536 字节，后者包含默认值和转义开销，避免接收后无法重新编码。标识符使用 `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`，区分大小写。

| 字段 | 必填 / 默认 | 规则 |
| --- | --- | --- |
| request_id | 必填 | 标识符；幂等键的一部分 |
| correlation_id | 可省略 | 显式提供时为非空标识符；只作跨 execution 关联 |
| requirements | 必填 | 下表；不接受自报 principal_id |
| operation | 必填 | 三种操作之一 |
| timeout_ms | 省略为 120000 | 1–3600000；运行超时，独立于审批 TTL；Node 可更严格 |

| requirements 字段 | 必填 / 默认 | 规则 |
| --- | --- | --- |
| os | 省略为 linux | v1 仅 linux |
| capabilities | 省略为空 | 最多 32 个标识符；规范化加入 operation.type 后排序去重；规范化后也不得超过 32 |
| resources | 必填 | 1–64 项 `{resource, revision?}`；同 URI 同约束去重，不同约束拒绝 |
| node_id | 可省略 | 标识符；硬约束，不能绕过权限和能力 |
| preferred_node | 可省略 | 标识符；只影响合法候选排序 |

resource 格式仅为 `repo://<标识符>` 或 `dataset://<标识符>`，不接受后续路径、URL 编码、query、fragment、端口或物理 root。revision 可省略，表示允许当前版本；指定时必须是 `{type,value}`：repo 仅 `git_commit`（40 或 64 位小写 hex，要求工作树 tracked/untracked 均 clean），dataset 支持 `owner_revision`（标识符，所有者声明）或 `sha256`（64 位小写 hex，内容摘要证据）。缺少所需证据或不匹配时不能降级执行。人工版本标签不代表系统计算了内容摘要。

`ResourcePath={resource,relative_path}` 两字段必填。relative_path UTF-8 最多 4096 字节，根写 `.`；其余为 `/` 分隔的非空段，无绝对路径、`.`/`..` 段、反斜杠、冒号、控制字符；不自动 clean 或 URL 解码。所有 target/cwd/path 参数引用必须在 requirements.resources 声明；额外声明仍是硬约束。Node 仍必须授权并执行目录句柄边界检查。

## operation

每个操作仅接受下列字段；即使其他操作字段为零或空，也不能混用。

| type | 字段 | 默认与限额 |
| --- | --- | --- |
| fs.list | target 必填；max_entries 可选 | 默认及上限 1000，下限 1；非递归，受结果正文总量限制，超额明确 truncated |
| fs.read | target 必填；offset、limit 可选 | offset 默认 0，0–9007199254740991；limit 默认 65536，1–65536；offset+limit 不得超过该安全整数上限 |
| process.exec | program、cwd 必填；args 可选 | program 是 Node 配置标识；args 默认 []，最多 256 项；不接受 env、shell 或物理 executable |

每项 arg 恰好含 `{literal:"..."}` 或 `{path:ResourcePath}`。literal 可为空，最多 4096 UTF-8 字节，禁止 NUL；包括空格、换行、`$()`、URI 字样的其他字符串原样作为一个 argv，绝不替换/插值。全部 literal 字节总和最多 32768。程序通过 Node 映射，不以 program 值直接查找 PATH；process.exec 默认 ASK 的授权规则仍由 Node 实现。

合法/非法完整示例集中在[契约样例](../资源/契约/README.md)，由自动测试读取，避免文档另存一份漂移样例。

## 规范化摘要与幂等

`DecodeRequest` 返回补齐默认值并排序去重的请求；仅成功后才可取摘要。摘要规范对象字段顺序为 correlation_id（存在时）、requirements、operation、timeout_ms，内部顺序由实现类型字段顺序固定。json 编码采用 Go encoding/json 的紧凑输出（包括 HTML 转义），输入中字段顺序、空白及等价 JSON 转义不影响结果。前缀 `runweave-request-v1\n` 后接规范对象 UTF-8，无尾部换行；SHA-256 小写十六进制外加 `sha256:`。

request_id 不进摘要，唯一键是来自认证上下文的 `(principal_id, request_id)`；correlation_id 进摘要。默认值与显式相同值等价；能力/资源集合顺序与相同重复项等价；argv 顺序、字符串原值、版本、timeout 和 placement 约束变化不等价。固定向量由 fixtures 保存。

生产提交顺序约定：认证与严格校验 → 规范化和摘要 → 查同键；同键同摘要返回原 ID（包括终态/UNKNOWN），不同摘要报 IDEMPOTENCY_CONFLICT；没有旧记录才执行当前授权/候选筛选，并在原子提交中再次检查同键、占槽和写入 execution。无合法候选或全部忙在创建 ID 前返回错误。原子提交竞争后必须重查原键，不能创建替代执行。已存在记录仍按当前调用者授权返回，不绕过撤销与内容策略。

只有事务提交确认后才能对外承诺新 ID。响应丢失/存储提交结果不确定时，客户端保持原 request_id 重试查询，不生成新键。MCP 请求取消或 bridge 关闭不会自动取消已提交 execution。此包不提供数据库幂等实现。

## 结果

`DecodeResult` 校验结果并补 mutations.coverage；`EncodeResult` 也必须校验后编码。完整结果 JSON 上限 1 MiB，正文（目录名字节和文件解码内容）合计上限 64 KiB；这两个上限分别检查。外层协议仍需在编码后校验完整帧 1 MiB，不把 Result 限额当 envelope 限额。

| 字段 | 必填 / 规则 |
| --- | --- |
| operation | 必填，三种操作名之一 |
| duration_ms | 必填，非负安全整数；客观耗时，不代表等待审批耗时 |
| resources | 必填数组，最多 64 个唯一 resource 的实际版本证据 |
| mutations | 可省略或省略 coverage；默认 `{coverage:"unknown"}`，仅接受 unknown / best_effort，不表示副作用回滚 |
| artifact_refs | 必填数组，最多 16 个唯一不透明 artifact_id 的元数据；不返回物理路径 |
| error | 可省略；有则为执行错误 `{code,message}`，message 非空、最多 1024 UTF-8 字节 |
| fs_list / fs_read / process | 只能出现与 operation 对应的一项；成功必须有；执行失败可无正文，保留可知的部分结果时可有对应正文 |

resources 的项为 `{resource,source,revision?,clean?}`。source=unknown 时无 revision/clean；source=git 时必须有 git_commit 和布尔 clean；source=owner_manifest 时必须有 owner_revision；source=content_digest 时必须有 sha256；后两者不得带 clean。结果记录实际证据，不单凭形状证明满足请求约束。

artifact_refs 项为 `{artifact_id,media_type,size_bytes,expires_at,truncated}`；ID 使用标识符规则，media_type 是最多 128 字节的有效 MIME 类型，size_bytes 非负安全整数，expires_at 是最多 64 字节、带时区的 RFC3339 时间。读取时逐次授权；元数据合法不等于 artifact 在线或未过期。

- fs_list：`{entries:[{name,kind,size_bytes?}],truncated}`；最多 1000 个唯一名字，name 为单个合法路径段、最多 255 UTF-8 字节；kind=file/directory/symlink/other；size_bytes 可选非负安全整数。不保证排序或分页快照，不返回符号链接目标物理路径。
- fs_read：`{offset,encoding,data,bytes_returned,eof}`；encoding=utf8 或 base64，base64 使用标准有 padding 编码；bytes_returned 必须等于解码后字节数且不超过 65536；offset 与 offset+bytes_returned 是非负安全整数。UTF-8 切片边界或二进制内容可用 base64，不能替换丢失字节后伪称原文。
- process：`{exit_code?,stdout_bytes,stderr_bytes,stdout_truncated,stderr_truncated}`；计数非负安全整数，记录实际产生字节而不只是保存字节；exit_code 为 0–255，0 才是成功结果。失败可省略 exit_code（例如进程未正常退出），正常非零退出使用 PROCESS_EXIT_NONZERO；没有原始 stdout/stderr 字段。

所有安全整数上限为 9007199254740991，避免跨 JSON 客户端精度丢失。返回内容、目录名、错误消息和产物元数据必须先做授权与脱敏；结构校验不能识别任意字符串是否含秘密。

## 错误与 ID

错误对象仅 `{code,message}`。分类不等同 HTTP status；HTTP/MCP 映射留至接入实现。错误消息不应回显完整请求、凭据或 Node 物理路径。

| 类别 | code | 是否新建 execution ID / 重试含义 |
| --- | --- | --- |
| 调用校验 | INVALID_REQUEST、REQUEST_TOO_LARGE、UNSUPPORTED_OPERATION、UNDECLARED_RESOURCE | 不新建；修正输入 |
| 认证/授权 | UNAUTHENTICATED、FORBIDDEN | 不新建；修复身份/权限 |
| 幂等冲突 | IDEMPOTENCY_CONFLICT | 不新建；已有记录不变，不自动换键重跑 |
| 放置失败 | NO_MATCHING_NODE、NODE_BUSY | 不新建；排除约束/资源或等待槽位，仍沿用原键 |
| 存储 | STORAGE_UNAVAILABLE | 不能承诺创建与否；若提交结果不确定，必须沿用原键重试，不能断言没有 execution |
| 查询/读取 | EXECUTION_NOT_FOUND、ARTIFACT_NOT_FOUND、ARTIFACT_UNAVAILABLE、ARTIFACT_EXPIRED | 不新建；不改变既有执行状态 |
| 执行 | POLICY_DENIED、APPROVAL_DENIED、APPROVAL_EXPIRED、RESOURCE_UNAVAILABLE、REVISION_MISMATCH、PROGRAM_UNAVAILABLE、PATH_DENIED、IO_ERROR、PROCESS_START_FAILED、PROCESS_EXIT_NONZERO、CANCELLED、TIMED_OUT、OUTPUT_LIMIT_EXCEEDED、INTERNAL_ERROR | 已有 ID；错误保存在执行结果中，不是提交 RPC 失败，不自动重执行 |

UNKNOWN 不是执行错误；取消意图不等于 CANCELLED。上述执行错误的状态映射和证据要求见[执行状态与证据](../设计/执行状态与证据.md)。结果结构不合法由本地校验返回 INVALID_RESULT；它属于开发/协议校验错误，不作为已验证的 Node 执行终态落库。

执行错误的触发条件如下；这些是生产者必须满足的语义，本包不能仅凭 JSON 证明真实执行事实。

| code | 已有 execution 后的触发条件 |
| --- | --- |
| POLICY_DENIED | Node 最终策略拒绝；静态候选全部不合法的提交仍使用 NO_MATCHING_NODE |
| APPROVAL_DENIED / APPROVAL_EXPIRED | 本地明确拒绝，或审批 TTL 到期且确认未启动 |
| RESOURCE_UNAVAILABLE / REVISION_MISMATCH | 启动前资源不可用，或实际版本/clean 证据不满足要求 |
| PROGRAM_UNAVAILABLE | 程序映射不存在或不再可用，不以 PATH 搜索替代 |
| PATH_DENIED | 路径边界或文件访问策略拒绝，不向客户端回传物理路径 |
| IO_ERROR | 授权范围内实际文件 I/O 失败；存储 journal 失败不能假装已有可信执行结果 |
| PROCESS_START_FAILED | 有证据确认本次启动失败；模糊启动窗口必须 UNKNOWN |
| PROCESS_EXIT_NONZERO | 已知正常退出、退出码 1–255，结果必须带相应退出码 |
| CANCELLED / TIMED_OUT | 明确取消/运行 deadline 且有停止与回收证据；仅收到取消请求或连接断开不能使用 |
| OUTPUT_LIMIT_EXCEEDED | 允许返回的结果无法在硬限额内表达且不能按操作规则截断；日志达到保存上限应继续排空并标记 truncated，不自动报此错误 |
| INTERNAL_ERROR | 已知执行失败的非预期内部错误；不能掩盖执行事实未知 |

## 验证与实现边界

源码、样例、固定摘要与实际结果见[本项验证](../验证/2026-09-10-P0业务契约验证.md)。本页的提交顺序、授权和 ID 规则是已决策要求；本阶段仅实现纯契约校验。MCP 六个业务工具、真实资源访问、数据库原子幂等、完整结果授权、结果与原请求的匹配尚未实现。后续接收结果时还须绑定 execution/请求摘要，验证操作类型、read offset/limit、list max_entries 与资源证据；不能只调用 DecodeResult 就信任结果。
