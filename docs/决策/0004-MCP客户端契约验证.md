# ADR 0004：MCP 客户端契约验证

状态：已接受。日期：2026-09-11。适用范围：P0 验收收尾 / MCP 业务契约 v1。维护责任：当前工作项开发者。

## 目的与决定

补齐[三个月规划](../../RunWeave3个月开发规划书.md)要求的六个工具名称/schema 与真实客户端联合验证。正式 Server/Node 尚未实现，因此采用独立 `cmd/mcp-contract-probe`，使用官方 Go SDK 的 stdio 协议和真实 Codex CLI；所有资源、执行与产物都是明确标注的内存样例，不开放真实文件、程序、网络或持久执行能力。

工具保持规划名称 `runweave.list_nodes/list_resources/execute/get_execution/cancel_execution/read_artifact`。输入沿用业务 Request，其他工具使用有界分页/标识符输入；统一输出为 `{data:具体结果}` 或 `{error:{code,message}}`，错误同时设置 MCP isError。ExecutionView 包含状态、取消意图、时间、Node、请求摘要、审批、placement 和可选 Outcome。

schema 从 Go 类型结构生成，显式补充操作/参数联合、字段枚举与限制；原始严格解码和业务校验仍是必需步骤。JSON Schema 不证明授权、字节大小、跨字段引用或整数原始字面量合法。输出先作语义与 schema 校验，再同时生成 structuredContent 和文本 JSON。

协议探针对 execute/cancel 使用正式语义的非只读工具标记，工具描述和 server instructions 明确为 P0 内存模拟。验证时仅对这六个已审阅的探针工具设置进程级许可，不写入全局配置。默认不改模型、不触碰登录凭据；沿用本机已登录的 Codex CLI。CLI 原始日志放入被忽略的 `.cache/`，只保留脱敏的实际 MCP 调用与服务端初始化/调用审计证据。

## 验收与限制

备选方案：只运行 SDK 自测无法证明真实客户端适配；复用旧 nonce 回显探针无法验证六工具业务 schema；等正式 Server/Node 实现后再测会推迟 P0 契约冻结。因此选择独立内存探针，代价是必须清楚区分模拟行为与生产执行，并在 P1–P5 重新验证实际链路。除 Codex 外的客户端暂不增加，符合规划的首选客户端与额外客户端不阻塞阶段原则。

本机 CLI 已安装；沙箱内 login status 的 Not logged in 不能证明用户未登录，系统权限下已确认 ChatGPT 登录。无须用户新建节点、提供 token、准备数据集或安装第二个客户端。

验收覆盖六工具实际调用、三种 operation 的 schema、同键同 ID/冲突、审批等待、取消意图与确认分离、有界产物读取、错误输出、实际协商协议/客户端版本。内存模拟只验证客户端能发现、构造和读取该契约，不代表 A02/A06 等业务验收，也不证明重启持久性。

依据：[官方 MCP 接入](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、[官方非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。实现与实际结果见[收尾验证](../验证/2026-09-11-P0真实客户端契约验证.md)，字段见[MCP 工具参考](../参考/MCP工具.md)。
