# ADR 0005：P1 配置与状态存储基础

状态：已接受。日期：2026-09-12。适用范围：P1-01/02 首批实现。维护责任：当前工作项开发者。

## 背景与范围

P0 已冻结业务与协议契约，但没有生产入口、配置或持久存储。P1 按[阶段规划](../../RunWeave3个月开发规划书.md)推进，首批建立可独立验证的启动前检查与存储基础；本记录先于实现。身份、连接、执行服务和 MCP bridge 的实际运行在后续工作项接入，不用内存探针代替生产服务。

## 决定与理由

- 引入 `cmd/runweave`、`internal/config`、`internal/store`。统一入口先提供 `version`、`config check --config`、`state init --config`；未实现的 daemon/bridge 命令明确失败。命令结果为 stdout JSON，诊断为 stderr JSON 日志，不输出配置内容或凭据。
- YAML 配置独立使用 `version: 1`，区分 `server`、`node`、`mcp` 角色。配置文件上限 64 KiB，单文档、严格字段和类型，拒绝重复键、锚点、别名、合并键及显式 null。路径以配置文件所在目录为基准；不展开环境变量。token 只允许文件引用，不允许在 YAML、参数或 URL 中内联。
- Server 监听地址只接受 IP 字面量和端口。非 loopback 必须配置 TLS 证书与私钥；客户端非 loopback URL 必须使用 HTTPS，不提供跳过证书校验选项。当前只校验配置约束，不宣称已实现网络认证或 TLS 服务。
- SQLite 沿用 ADR 0001 的版本，不引入依赖。每个状态目录先取得 OS 非阻塞独占锁，再开库；Linux 用 `flock`，Windows 用 `LockFileEx`。锁文件持续保留，进程退出由 OS 释放锁，禁止用 PID 文件存活判断或删除锁文件恢复。
- 状态目录内使用固定 `state.db` 和 `daemon.lock`。Server/Node 有各自迁移序列，第一版只创建迁移历史与持久存储身份（角色、随机实例 ID、创建及最近写入检查时间）；后续业务表随对应设计新增迁移。不开空业务表来冒充持久 execution。Node 的实例 ID 将供 journal 对账使用，删除状态后不得沿用旧身份接入。
- 使用显式 SQL、单连接、WAL、外键、`busy_timeout=1000`、`synchronous=FULL`；用驱动连接参数在每次新建连接时设置连接级 PRAGMA。每次打开验证完整迁移历史、顺序及 SQL 校验和，未知版本、改写历史、角色不符均失败。待执行迁移与历史记录同事务；启动前提交一次真实写入检查，不在事务内等待网络。
- 关闭顺序为数据库后锁；失败路径释放已取得的资源。状态目录必须在本机磁盘上、由专用 OS 账号保护，不承诺对同账号恶意目录/锁文件替换提供隔离。Linux 新目录/文件限权，Windows 继承目录 ACL，不能把 `0600` 当成 Windows ACL 保障。

## 备选方案与后果

不采用仅创建 PID 文件的锁：进程崩溃会残留文件且 PID 可复用。不引入跨平台锁依赖：现有 `x/sys` 足以覆盖首批 Windows/Linux；其他平台明确不支持。不采用通用 ORM/迁移框架：当前两类小型库用内嵌 SQL 与顺序事务即可核验。

不预建全部 execution/审批/产物表，避免尚未实现的事务语义被过早固定。代价是 P1-03/05/06/07 需要追加迁移及数据参考。首批 `state init` 是短时持锁的初始化/检查命令，不是 daemon；未来 daemon 必须在整个运行期间持有同一 Store。

只支持停机备份：停止全部访问者，完整复制状态目录到受保护的位置；还原保留角色、实例 ID 与数据库配套文件。禁止在线只复制主库、跳过迁移记录或把新版本库交给旧版本自动降级。具体步骤与实际验证在首批交付文档中补齐。

## 验收与后续

首批检查严格配置负例、stdout/日志分离、迁移失败回滚、持久身份重开稳定、库角色隔离、未来/篡改版本拒绝、实际子进程锁竞争与强制退出后释放、不可写拒绝和停机复制恢复。Windows 与 WSL 分别记录实际结果，未执行的环境不标通过。

本决定不替代 ADR 0001–0004，不修改 P0 契约。P1 完整出口仍要求身份撤销、Node 会话/对账、持久提交与幂等、授权目录句柄访问、结果 receipt 以及真实客户端与 CLI 同记录证据。
