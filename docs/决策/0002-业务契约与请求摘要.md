# ADR 0002：业务契约与请求摘要

状态：已接受。日期：2026-09-10。适用范围：P0-02 / 业务契约 v1。维护责任：当前工作项开发者。

## 背景与范围

按[三个月规划](../../RunWeave3个月开发规划书.md)先冻结明确操作，再实现持久提交。当前没有 Server/Node；本项新增仅依赖 Go 标准库的 `internal/contract`，负责严格 JSON 解码、三种操作校验、默认值与集合规范化、请求摘要及有界结果校验。不会分配 execution ID、读写资源、执行程序或判断调用者权限。

## 决定

1. 使用带 `type` 的操作对象，按 `fs.list`、`fs.read`、`process.exec` 区分合法字段。进程参数统一为互斥的 `{literal: string}` 或 `{path: ResourcePath}`，cwd 必须显式引用资源；不添加 env 或隐式 shell。
2. 业务 JSON 严格区分字段大小写，拒绝未知字段、重复键、null、多根值、无效 UTF-8、孤立 UTF-16 surrogate 和过深嵌套。可选字段只能省略；整数不接受浮点/指数表示。避免不同接入层对同一输入解释不一致。
3. 资源仅 `repo://` 和 `dataset://` 的逻辑标识。路径为统一 `/` 相对路径，根为 `.`；拒绝绝对路径、空段、`.`/`..` 子段、反斜杠、冒号与控制字符。它是语法边界，不替代 Node 的目录句柄和符号链接安全检查。
4. 规范化补齐默认值，能力集合排序去重并包含操作本身，资源按 URI 排序去重；同一 URI 的不同 revision 拒绝。所有实际引用必须在 requirements 声明。保留 argv 顺序、literal 原值及 Unicode 原值，不进行 trim、Unicode 归一化或 URI/路径解码。
5. 摘要为 `sha256:` 加十六进制 SHA-256，输入是 `runweave-request-v1\n` 和本包确定的规范 JSON。排除 request_id（它是幂等键）与 principal_id（它来自认证），包括 correlation_id、完整 requirements、operation、timeout_ms。这是本项目的版本化格式，不宣称采用跨语言通用规范 JSON 标准；提供固定向量供后续客户端复核。客户端不自行指定可信摘要。
6. 结果正文默认不携带原始日志；目录、文件内容、进程计数、版本证据和不透明产物元数据分开表达。mutations.coverage 省略时补 unknown，不能推断无副作用。输出是否合法不等于有权返回该内容。

## 备选与代价

直接 hash 原始 JSON 会把字段顺序、默认值和集合顺序差异误判为冲突；只 hash operation 会漏掉超时、版本、路由与关联变化。依赖宽松解码会接受重复键、大小写别名等歧义，因此增加小型严格解码辅助函数。业务字段的结构由 Go 类型唯一维护，不另手工复制一套 JSON Schema；P1 的 MCP inputSchema/outputSchema 从适配层生成并验证与本包一致，不能用客户端 schema 代替服务端校验。

统一参数对象较纯字符串 argv 冗长，但保留 literal/path 的明确边界。严格路径会拒绝部分 Linux 合法文件名，首版不通过猜测转义放宽；后续扩展需更新契约版本与测试。

## 验收与兼容

具体字段、默认值、错误与 ID 行为见[业务契约](../参考/业务请求与结果.md)。以合法/非法 JSON fixtures、摘要固定向量、字段/字节边界、错误分类、重复/大小写/null/Unicode 负例验证。生产原子幂等、认证、路由、安全访问和状态转换分别留给 P1 与 P0-03；不能将本项标为 A06 完整通过。

本版本尚未发布。后续改变摘要算法、默认值或字段语义必须提升摘要版本并保留旧执行的版本信息，不用新规则重新计算旧记录；无数据库迁移发生。相关实现与证据将在[验证记录](../验证/2026-09-10-P0业务契约验证.md)关联。
