# ADR 0003：执行证据与 Node 协议

状态：已接受。日期：2026-09-11。适用范围：P0-03 / Node 协议 v1。维护责任：当前工作项开发者。

## 背景与决定

[三个月规划](../../RunWeave3个月开发规划书.md)要求未知执行继续占槽、旧 epoch 无效、可信终态可跳过中间通知、Node 结果提交后才确认。本项以纯函数落实证据规则，仍不实现数据库、会话服务或执行器。

1. contract 定义执行状态、Node journal 阶段和单调 revision。只有持久 Node 证据可恢复进度；心跳不改变 execution。连接丢失使非终态 UNKNOWN，取消意图独立保存。UNKNOWN 继续占槽。
2. 为每个 execution 记录 Node revision 与证据摘要。同 revision 不同内容视为冲突，低 revision 视为迟到。重复终态不得改写；同一结果允许重发 receipt，冲突结果只留冲突事件。真实数据库必须将状态、槽位、revision 与事件原子写入。
3. 使用显式终态 Outcome：状态、启动事实、清理确认和业务 Result。没有清理证据不能释放槽位；启动承诺后的模糊窗口映射 UNKNOWN，不自动重跑。Outcome 摘要绑定 receipt，独立于请求摘要。
4. Node 协议 envelope v1 与业务请求、摘要、MCP、软件版本分开。业务字段严格拒绝未知字段；仅 envelope.extensions 允许忽略有界可选扩展，不能改变授权/派发/确认等必需语义。协议不协商降级，未知 type/version 拒绝。
5. register 是已认证连接上的首次消息，epoch 为空；registered 由 Server 返回新 epoch。之后所有帧必须匹配当前认证 Node/连接方向/epoch，重连先取消与对账，再允许调度。配置更新以新连接完整快照重新注册。
6. 抽取 P0-02 的严格 JSON 辅助到 internal/strictjson，供 contract 与 protocol 共用；contract 不依赖 protocol。protocol 只定义消息与校验，不管理网络、认证或持久化。

## 备选、代价与后果

仅按到达顺序更新状态无法区分迟到 accepted 与新 snapshot；仅用 message_id 不能表达 journal 演进。因此增加每 execution 的持久 revision 与证据摘要，Node 重新报告必须沿用原事实。重装丢失 journal 不能从 revision=1 重接旧身份，必须隔离并撤销旧身份。

不把在线当作已对账，不把缺失 journal 记录当作未执行，不用 PID 存在性宣称清理完成。代价是不可证明的窗口会长期 UNKNOWN，占用唯一槽位，需要操作者调查；这是规划中的安全语义，而不是故障后自动补偿。

协议复用业务 Result，通过 Outcome 摘要确认完全相同的持久结果。P0 只校验声明形状与转换一致性，无法证明 Node 声明真实；后续启动 journal、操作系统回收、查询相关性、数据库事务和身份 fencing 必须提供实测证据。
