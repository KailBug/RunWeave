# P1 启动前检查与状态目录

状态：现行。更新日期：2026-09-12。适用范围：v0.0.1-dev / P1 首批。维护责任：当前工作项开发者。

## 目标与前提

本指南用于构建统一 CLI、检查配置、初始化并恢复状态目录。当前没有 Server/Node daemon、网络连接或正式 MCP bridge；执行这些命令不会启动文件访问服务。配置检查通过不代表凭据、证书、授权资源或远端连接已可用。

需要 Go 1.27.0、已获取的 go.mod/go.sum 依赖及可写本机状态目录。开发机已验证 Windows amd64 与 Ubuntu WSL2 amd64；不要求本指南步骤具有管理员权限。Windows 状态目录使用受保护的用户目录 ACL；Linux 新目录使用 `0700`，不要放在共享/网络盘。

## Windows 构建与预检

PowerShell，工作目录仓库根目录（本机 `D:\RunWeave`）。构建产物在忽略的 `bin/`；后续初始化在忽略的 `state/` 创建 SQLite 数据。

```powershell
$env:GOPATH = "$PWD/.cache/gopath"
$env:GOMODCACHE = "$PWD/.cache/gomod"
$env:GOCACHE = "$PWD/.cache/gobuild"
go build -o bin/runweave.exe ./cmd/runweave
./bin/runweave.exe version
./bin/runweave.exe config check --config docs/资源/P1配置/server.yaml
./bin/runweave.exe config check --config docs/资源/P1配置/node.yaml
./bin/runweave.exe config check --config docs/资源/P1配置/mcp.yaml
```

逐条检查 `$LASTEXITCODE`。预期版本为 `0.0.1-dev`、stage 为 `p1-foundation`；配置预检 stdout 返回 `valid: true` 及对应角色，诊断在 stderr。不读取样例中的 token 文件，因此不需要创建伪造 token 来通过检查。字段、上限与负例见[参考](../参考/配置与状态存储.md)。

```powershell
./bin/runweave.exe state init --config docs/资源/P1配置/server.yaml
./bin/runweave.exe state init --config docs/资源/P1配置/server.yaml
./bin/runweave.exe state init --config docs/资源/P1配置/node.yaml
```

预期前两次返回相同的 `instance_id`，`role: server`、`schema_version: 1`；Node 使用独立目录，返回 `role: node` 和另一个实例 ID。运行后命令退出，锁释放但 `daemon.lock` 文件保留。不要将 Server/Node 指向同一目录。`state init` 不支持 `role: mcp`。

## 停机备份与恢复检查

仅对已经停止全部访问者的状态目录执行；不能在线复制单独主库。本示例创建全新备份和恢复副本，不覆盖原库。首批库没有用户 token 或 execution，但应从一开始保护整个目录。未来有身份和业务数据后，不能让原实例与恢复副本同时上线。

PowerShell，仍在仓库根目录，先完成上面的 Server 初始化。

```powershell
$stateSource = Join-Path $PWD.Path 'state/p1-server'
$backupStamp = Get-Date -Format 'yyyyMMdd-HHmmss-fff'
$stateBackup = Join-Path $PWD.Path "state/p1-backup-$backupStamp"
$stateRestore = Join-Path $PWD.Path "state/p1-restored-$backupStamp"
if ((Test-Path -LiteralPath $stateBackup) -or (Test-Path -LiteralPath $stateRestore)) {
    throw '目标已存在，不能覆盖'
}
Copy-Item -LiteralPath $stateSource -Destination $stateBackup -Recurse
Copy-Item -LiteralPath $stateBackup -Destination $stateRestore -Recurse
$restoreConfig = Join-Path $PWD.Path "state/p1-restore-$backupStamp.local.yaml"
@"
version: 1
role: server
state_dir: ./p1-restored-$backupStamp
server: {}
"@ | Set-Content -LiteralPath $restoreConfig -Encoding utf8
./bin/runweave.exe state init --config $restoreConfig
```

比较恢复命令的 `instance_id` 与源初始化结果，应完全相同。`last_checked_at` 会变更，说明恢复库完成了一次实际写入检查。若源仍被服务持有，不进行以上复制，先有序停止；本批尚无专门备份命令或在线备份功能。

未知 schema/历史校验失败时停止，不删历史记录、不降级 SQL；改用匹配版本的软件或恢复与旧软件匹配的停机备份。旧 P0 实验库没有产品迁移历史，不能原地升级。清理本示例产物时先核实绝对路径及已无访问者，只清理自己新建的测试目录，不删除正在使用的库/锁/WAL。

## Linux / WSL 验证

可原生使用 Go 1.27.0 构建；本次 WSL 没有 Go/gcc，使用 Windows 交叉编译产物实际运行。以下 PowerShell 命令应在独立会话运行，避免 GOOS/CGO 设置影响 Windows 构建。

```powershell
$env:GOPATH = "$PWD/.cache/gopath"
$env:GOMODCACHE = "$PWD/.cache/gomod"
$env:GOCACHE = "$PWD/.cache/gobuild"
$env:GOOS = 'linux'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go build -o bin/runweave-linux-amd64 ./cmd/runweave
go test -c -o bin/p1-store-linux-amd64.test ./internal/store
go test -c -o bin/p1-config-linux-amd64.test ./internal/config
go test -c -o bin/p1-cli-linux-amd64.test ./cmd/runweave
wsl -d Ubuntu --exec /mnt/d/RunWeave/bin/p1-store-linux-amd64.test '-test.v' '-test.timeout=60s'
wsl -d Ubuntu --cd /mnt/d/RunWeave/internal/config --exec /mnt/d/RunWeave/bin/p1-config-linux-amd64.test '-test.v' '-test.timeout=30s'
wsl -d Ubuntu --exec /mnt/d/RunWeave/bin/p1-cli-linux-amd64.test '-test.v' '-test.timeout=30s'
```

逐条检查退出码；配置测试需要指定包目录才能找到文档样例。存储和 CLI 测试在 WSL 原生临时目录创建状态，而非把 Windows 示例库直接作为 Linux 状态目录。覆盖实际锁竞争、强制退出后恢复、迁移与停机复制。完整测试名与边界见[验证记录](../验证/2026-09-12-P1配置与状态存储验证.md)。

## 排障与退出

| 现象 | 处理 |
| --- | --- |
| `invalid config...` | 对照样例检查单文档、未知字段、重复键、类型、角色和版本；不把原始含密配置粘贴到日志 |
| 非 loopback HTTP 或监听 TLS 配对错误 | 客户端改为 HTTPS；Server 配置成对证书与私钥引用；后续服务启动还须验证实际证书 |
| `state directory is locked...` | 找到持有同目录的进程并正常停止；文件存在本身不是占锁依据，不删除锁文件 |
| 角色/历史/实例身份错误 | 核实正确配置、状态目录和软件版本；保留现场，不通过手改数据库跳过检查 |
| 目录/数据库不可写 | 修复实际用户的目录权限、Windows ACL 或只读属性；不要以可读代替可写，不轻易删除持久状态 |
| `daemon and mcp serving are not implemented yet` | 本批只有预检与初始化；跟踪 P1 后续开发进度 |

命令完成后自动关闭数据库和锁；中断会取消上下文并退出。崩溃释放锁不证明任何 execution 已清理，执行恢复/UNKNOWN 语义仍由后续 P1/P4 落地。
